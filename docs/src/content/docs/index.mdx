A **doko** (डोको) is the woven bamboo basket carried across the hills of Nepal. Firewood, grain, a week of supplies: whatever the load, it all goes in the basket, and a single strap, the *namlo*, carries the weight.

doko works the same way for Rust on Cloudflare Workers. Routing, config, storage, caching, background jobs, cron, Durable Objects, auth, email, Postgres and AI all go in the basket. You carry one `doko.toml`, and doko writes the `wrangler.toml`, typed bindings and glue code you'd otherwise maintain by hand.

## Quick start

```bash
rustup target add wasm32-unknown-unknown
cargo install doko-cli
doko new my-app && cd my-app && doko dev
```

## What's in the basket

| | |
|---|---|
| [Routing and handlers](/doko/guides/handlers/) | axum routers, a `Ctx` extractor, JSON errors, request logs, validation, CORS and secure headers, an error hook |
| [Config and environments](/doko/guides/configuration/) | typed config merged per env, vars and secrets, any wrangler setting through `[wrangler]` |
| [Storage](/doko/guides/storage/) | typed KV, R2 and D1 bindings, plus D1 migrations |
| [Cache](/doko/guides/cache/) | response caching with stale-while-revalidate and global tag purges |
| [Jobs and cron](/doko/guides/jobs-and-cron/) | Queues-backed jobs with retries and a dead-letter queue, named cron tasks |
| [Durable Objects](/doko/guides/durable-objects/) | a `DurableObject` trait, typed stubs, and a per-route rate limiter built on them |
| [Auth](/doko/guides/auth/) | cookie sessions, JWTs, password hashing, `.require_auth()` |
| [Email](/doko/guides/email/) | sending through a typed binding, receiving in `Hooks::on_email` |
| [Postgres](/doko/guides/postgres/) | Hyperdrive-backed queries in D1's shape, with migrations (feature `pg`) |
| [Workers AI](/doko/guides/workers-ai/) | `ctx.ai()` with serde types, and streamed answers |
| [Analytics Engine](/doko/guides/analytics-engine/) | typed data points through `ctx.analytics()`, and SQL reads |
| [The `doko` command](/doko/reference/cli/) | `routes`, `doctor`, `db seed` and `reset`, a SQL `console`, and a deploy that checks secrets and migrates first |
| [Generators](/doko/guides/generators/) | `doko new`, `generate scaffold \| auth \| controller \| job \| mailer \| migration` |
| [Integration tests](/doko/guides/testing/) | `doko::test` runs your worker under `wrangler dev` |

doko is built on [`worker`](https://crates.io/crates/worker) and axum, in the spirit of Rails and Loco. See the [roadmap](https://github.com/wheregmis/doko/blob/master/ROADMAP.md) for what's next.
